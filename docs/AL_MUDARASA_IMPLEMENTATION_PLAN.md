# خطة تنفيذ قسم «المدارسة» في الربانيون

> المرجع الأساس لتطوير المدارسة. تُحدَّث هذه الوثيقة بعد كل مرحلة، وتُعلَّم المهمة `[x]` فقط بعد تنفيذها **واختبارها** فعليًا. أي متطلب لم يُنفَّذ يبقى `[ ]` ولا يُحذف.

## 1. تعريف المدارسة وفلسفتها

«المدارسة: مساحة يجتمع فيها أعضاء الربانيون على طلب العلم، يتفقون على قراءة كتاب أو دراسة موضوع أو الاستماع إلى سلسلة علمية، ويتعاونون على الفهم والتذاكر، ويتبادلون الفوائد والملاحظات والأسئلة، ويعقدون اللقاءات لمناقشة ما تعلموه؛ ليكون طلب العلم رحلة مشتركة يعين فيها بعضهم بعضًا على الفهم والعمل».

**المبدأ الحاكم:** ليس المقصود إنهاء أكبر عدد من الكتب، وإنما التعاون على فهم العلم وتثبيته والانتفاع به والعمل به.

**ما ليست عليه المدارسة:** ليست شبكة اجتماعية ولا دردشة مفتوحة؛ كل مدارسة مرتبطة بمادة علمية وهدف واضح، والانضمام منضبط، والمشاركات خاصة بالأعضاء، ولا ترتيب تنافسي ولا قوائم متأخرين.

## 2. المتطلبات الوظيفية (ملخصًا)

| المجال | المتطلب |
|---|---|
| الأنواع | متزامنة / غير متزامنة / بإشراف معلم |
| المادة | كتاب، سلسلة دروس، محاضرات مرئية أو صوتية، موضوع علمي |
| التصنيف | عقيدة، تفسير، حديث، فقه، سيرة، تزكية، أخرى |
| المشاركة | دعوات فقط، أو طلب انضمام + موافقة (لا انضمام عشوائي) |
| الخطة | تاريخ بداية/نهاية، مقدار الإنجاز (صفحات/فصول/دروس/دقائق) يوميًا أو أسبوعيًا |
| الصفحة | 8 تبويبات: نظرة عامة، المادة، الخطة، الفوائد، النقاش، الاجتماعات، الخلاصة، الأعضاء |
| الفوائد | 6 أنواع مشاركات + تعليق + تفاعل «فائدة نافعة»، خاصة بالأعضاء |
| الأسئلة | مستقلة عن الفوائد، إجابة معلم موثقة مميّزة، علامات «تمت الإجابة» و«تحتاج مراجعة» وتثبيت |
| الاجتماعات | روابط Google Meet يدوية، حضور، ملخص، نقاط معلقة |
| الخلاصة | تجميع الفوائد المعتمدة مع حفظ نسبة كل فائدة لصاحبها، اعتماد نهائي |
| الإشعارات | دعوة/قبول/مادة/خطة/فائدة/رد/اجتماع/ملخص/اكتمال — قابلة للتحكم |
| الخصوصية | لا يرى غير العضو شيئًا؛ تقدم العضو شخصي؛ الإجمالي مجهول الاسم |

## 3. واجهات المستخدم

- **قائمة المدارسات** (`study` view الموجودة): تعريف المدارسة + زر «إنشاء مدارسة» + قائمة مدارساتي + «اكتشف المدارسات» (المتاحة بالطلب فقط، لا دليل عام للدعوات الخاصة).
- **إنشاء مدارسة**: نموذج بحقول المعلومات الأساسية + المادة + إعدادات المشاركة + الخطة.
- **صفحة المدارسة**: رأس (الاسم، النوع، الحالة، الأعضاء، التقدم الجماعي، الاجتماع القادم) + 8 تبويبات.
- **حالات**: تحميل/فراغ/خطأ لكل قائمة؛ حالة المدارسة (نشطة/مكتملة/متوقفة/ملغاة) ظاهرة دائمًا.
- **التصميم**: الهوية الحالية (أخضر داكن/رمادي، بيج، حدود ناعمة، Tajawal)، RTL كامل، متجاوب، بلا زخارف مبالغ فيها.

## 4. قاعدة البيانات (المرحلة الأولى — مطبَّقة)

قرارات تسمية: النظام الجديد يستخدم بادئة `study_circle*` و`study_material*` و`study_plan*`. جداول `study_tracks/parts/progress` القديمة (ترحيل 0016) تبقى كما هي للتوافق؛ لا تُوسَّع لأن دلالتها أرقع (مسار فردي) والدلالة الجديدة أوسع (مدارسة جماعية).

| الجدول | الغرض | حقول مفتاحية |
|---|---|---|
| `study_circles` | المدارسة | title, description, goal, kind(book/series/lectures/topic), category(7), mode(sync/async/supervised), access(invite/approval), status(active/paused/completed/cancelled), starts_on, ends_on, pace_target, pace_unit, pace_period |
| `study_circle_members` | الأعضاء والأدوار | (circle_id,user_id) PK, role(creator/supervisor/teacher/member) |
| `study_circle_invites` | دعوات برمز عشوائي | token_hash فريد (SHA-256)، expires_at، max_uses، uses_count، status |
| `study_circle_join_requests` | طلبات الانضمام | status(pending/accepted/rejected)، note، decided_by/at؛ فهرس فريد جزئي لمنع تكرار الطلب المعلق |
| `study_materials` | المواد | kind(book/video/audio/pdf/other)، title، author، url، position |
| `study_material_parts` | فصول/صفحات/دروس | material_id + circle_id (مُرَدَّد لتسريع السياسات)، page_start/end، url، is_required |
| `study_plan_tasks` | مهام الخطة | position، title، material_id؟، part_id؟، target_date؟ |
| `study_task_progress` | إنجاز العضو | (task_id,user_id) PK + circle_id؛ **خاصة بصاحبها** (RLS) |

**القرارات التقنية المهمة:**
1. **البصمة لا النص**: رمز الدعوة يُخزَّن SHA-256 فقط (نمط group_invites المجرَّب)؛ تسريب القاعدة لا يصنع روابط.
2. **العضوية شرط القراءة**: RLS لكل الجداول عبر `is_study_member` (SECURITY DEFINER لمنع التداخل، بنمط `is_group_member`).
3. **لا حذف للخطة عند التعديل**: `set_study_plan` يعمل upsert بالموضع (position) لا delete-all، حتى لا تُمحى سجلات الإنجاز (متطلب §6).
4. **التقدم الفردي خاص والإجمالي مجهول**: `study_task_progress` يقرؤه صاحبه فقط؛ الإجمالي عبر RPC يجمع أعدادًا بلا أسماء (نمط TAW-008).
5. **دور المعلم مشروط**: إسناد دور `teacher` يرفض غيرَ المعتمد (`is_approved_teacher`) — صلاحية المراجعة العلمية لا تُمنح بلا تأهيل.
6. **الإشعارات**: يوسَّع قيد `kind` ليشمل `mudarasa`، وتُدرَج الإشعارات داخل RPCs المدارسة نفسها بعد التحقق من الصلاحية (لا عبر `send_notification` العامة).
7. **الكتب الجاهزة**: الربط بمكتبة المنصة (public/books) يبقى للمرحلة التالية؛ المرحلة الأولى تقبل رابطًا وبيانات كتاب (يكفي لاختبار السيناريو).

## 5. الصلاحيات (مطبَّقة على الخادم لا الواجهة فقط)

| العملية | creator | supervisor | teacher | member |
|---|---|---|---|---|
| تعديل بيانات/حالة المدارسة | ✓ | — | — | — |
| إنشاء/إلغاء دعوة، قرار الانضمام | ✓ | ✓ | — | — |
| إسناد الأدوار (supervisor/teacher/member) | ✓ | — | — | — |
| إضافة/حذف مادة أو جزء | ✓ | ✓ | ✓ | — |
| تعديل خطة الدراسة | ✓ | ✓ | — | — |
| تسجيل الإنجاز | ✓ (كعضو) | ✓ | ✓ | ✓ |
| قراءة المحتوى والفوائد والأسئلة | ✓ | ✓ | ✓ | ✓ |
| مغادرة المدارسة | — (يغلقها بدلًا) | ✓ | ✓ | ✓ |

ملاحظات: creator لا يُزال ولا يغادر (يغلق المدارسة أو يبقيها)؛ إسناد teacher يتطلب اعتمادًا؛ لا ترقية ذاتية إطلاقًا (كل الإسناد عبر RPC يتحقق من دور الفاعل).
